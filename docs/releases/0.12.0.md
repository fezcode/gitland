# Gitland 0.12.0

## Windows release

Download and run **Gitland-Setup-0.12.0.exe**. The installer places Gitland in `%LOCALAPPDATA%\Programs\Gitland`, creates the shortcuts you select, and registers an uninstall entry in Apps & Features. The .NET runtime is included.

## Your repositories are on the welcome screen

The welcome screen lists the repositories you have opened, newest first. Clicking one opens it.

The list records every successful open, so a repository you cloned or created is there too, not only ones picked through the folder browser. A folder that has since been moved or deleted stays in the list, marked in amber as missing, rather than disappearing without explanation or failing only once you click it — and clicking it offers to drop it from the list. Each entry has its own menu: open it, copy its path, reveal it in File Explorer, or remove it from the list.

## Right-click any file

Every file in every tab now has a context menu, and its contents follow that file:

| The file you right-clicked | What the menu offers |
| --- | --- |
| Unstaged, tracked | Stage file · Discard changes… |
| Staged | Unstage file · Discard all changes… |
| Untracked | Stage file · Delete file… · Add to .gitignore |
| Conflicted | Open merge editor · Take ours · Take theirs |

Every file, whatever its state, also offers Blame, History of this file, Rename or move…, Copy path, Copy file name, and Reveal in File Explorer.

A conflicted file is deliberately not offered **Stage file**. Staging a conflict tells Git it is resolved without resolving anything, which is rarely what anyone means by clicking it.

## Delete permanently

Discarding and deleting have always saved your work first — tracked changes into a recovery commit, untracked files into the repository's recovery folder. Sometimes that is not what you want.

Every discard and delete dialog now carries a **permanent** option. It is off by default, it states plainly that nothing will be kept, and the confirm button changes to say **Delete permanently** or **Discard permanently** while it is ticked, so the button itself tells you what is about to happen. It applies to untracked deletion and to discarding tracked changes alike — a file, a hunk, or everything.

## A note on settings

`UserSettings` now carries the recent-repository list. Because it is a record, adding a list to it would have compared by reference and quietly broken settings round-tripping; equality is written out explicitly, and a test fails if a future setting is added without being accounted for there. Existing settings files load unchanged and simply start with an empty list.
