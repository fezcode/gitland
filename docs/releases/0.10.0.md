# Gitland 0.10.0

## Windows release

Download and run **Gitland-Setup-0.10.0.exe**. The installer places Gitland in `%LOCALAPPDATA%\Programs\Gitland`, creates the shortcuts you select, and registers an uninstall entry in Apps & Features. The .NET runtime is included. Git must be installed and on PATH; GitHub actions also require the GitHub CLI and authentication.

## You can undo your changes

Until now Gitland could only move a change between the working tree and the index. It could never throw one away, which left stash as the only exit. That gap is closed, and it is closed the way the rest of Gitland treats destructive work — nothing is lost silently.

- **Discard** a single hunk, a whole file, or every change in the repository, and delete untracked files.
- Discarding from the unstaged view keeps what you have already staged; discarding from the staged view returns the file to its last commit.
- Before anything is removed, tracked work is snapshotted into a commit recorded under **Repository → Recovery**, and untracked files are copied into the Git directory's `gitland-backups` folder. Both are restorable.
- **Hard reset** joins soft and mixed, recording both the abandoned commit and the overwritten working tree.

## Everyday operations that were missing

- **Amend** can now fold the staged index into the last commit, not just rewrite its message.
- **Unstage a hunk**, the counterpart to hunk staging.
- **Forced push** using `--force-with-lease`, so amending or rebasing no longer leaves you unable to push, and a teammate's commits are still never overwritten.
- **Pull** runs fast-forward, merge, or rebase, and can stash your changes first instead of refusing to run.
- **Fetch** can prune deleted remote branches.
- **History search** by message or author now runs in Git, so a match older than the loaded page is found instead of missed.
- **File history** for the selected file.

## Investigate and rewrite

- **Interactive rebase.** Reorder commits, and set each to pick, reword, edit, squash, fixup, or drop. The plan is validated before it runs and handed to Git directly, so no editor opens and a plan that could not finish is refused rather than abandoned half-way.
- **Blame** for the selected file, and **reflog** browsing.
- **Bisect** with good, bad, and skip.
- **Cherry-pick a run** of commits, and **revert a merge commit** by choosing which parent to keep.
- **Take ours or theirs** for a whole conflicted file, without opening the merge editor.

## Previously out of scope

- **Submodules**: add, update, and sync.
- **Git LFS**: read and edit tracked patterns.
- **Hooks** listing, **commit signature verification**, **patch** export and apply, and **archive** a revision as a zip.
- **Move or rename** a tracked file, and **add a pattern to .gitignore**.
- **GitHub Enterprise** hosts, replacing the hardcoded github.com.

## Also

The open repository is watched, so edits made in your editor appear without pressing F5. Refreshes are coalesced and never run while a merge result has unsaved edits.

- 190 offscreen native UI checks passed.
- Setup verified as a GUI-subsystem executable and reported with its SHA-256 checksum.

## Upgrading

Discard snapshots are ordinary Git objects and ordinary files. They survive restarts, but `git gc` prunes unreachable recovery refs on its own schedule and deleting the repository deletes both. Treat discard as recoverable for the session, not as an archive.
