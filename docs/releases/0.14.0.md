# Gitland 0.14.0

## Windows release

Download and run **Gitland-Setup-0.14.0.exe**. The installer places Gitland in `%LOCALAPPDATA%\Programs\Gitland`, creates the shortcuts you select, and registers an uninstall entry in Apps & Features. The .NET runtime is included.

## Every repository in one place

A **Workspace** entry now sits at the top of the navigation rail. Point it at the folder your repositories live in and every one of them appears in a single table, so the question "what have I left unfinished?" is answered by looking rather than by opening eight repositories in turn.

The folder is chosen once and remembered. Only repositories directly inside it are listed; a repository nested deeper is not, which keeps the scan to one directory read rather than a walk of your whole disk. A linked worktree or a submodule checkout carries `.git` as a file instead of a folder, and both are listed.

### What a row tells you

| Column | Shows |
| --- | --- |
| Repository | The folder name |
| Branch | The current branch, or `HEAD (detached)` |
| Changes | `clean`, or `+` new, `~` modified, `−` deleted, `!` conflicted |
| Sync | `↑` commits waiting to push, `↓` commits waiting to pull |
| Remotes | How many remotes are configured, or `local` for none |

Conflicts get their own count rather than being folded into "modified". Gitland is a merge client, and a repository stopped mid-merge is not the same as one with edits in it.

A repository that cannot be read — a broken `gitdir`, a folder Git refuses on ownership grounds — keeps its row and shows the reason. One unreadable folder never blanks the table.

### Narrowing the list

Filter by name, or switch to **Unclean** or **Clean**. Unclean means uncommitted work *or* commits not yet exchanged with the remote, so a repository with a spotless working tree and three unpushed commits still counts. That is the reading `atlas.radar --show unclean` uses, and it is the one that answers the question the table is for. The context bar keeps the running total: *4 of 8 need attention*.

Choosing a row opens that repository. Right-clicking one offers Open, Reveal in File Explorer, Copy path, and a fetch for that repository alone.

### Acting on all of them

**Fetch all** brings the `↑`/`↓` counts up to date without touching a branch or a working tree, so it simply runs. **Pull all** and **Push all** change history or publish it, so each one first names every repository it would touch and does nothing at all unless you confirm:

- Pull skips repositories with uncommitted changes, and says how many it skipped.
- Push covers only repositories that have somewhere to push and something to send.
- Neither ever forces.

All three respect the filter currently applied, so narrowing to one project's repositories and fetching covers those and no others.

### Staying current

While the view is open, the folder is watched. A commit you make in another tool updates its row on its own: an event is matched back to the repository it happened in, and only that row is re-read, after the burst of writes settles. Leaving the view stops the watching, so the diff and merge views pay nothing for it. F5 rescans everything.

## Two fixes for Git 2.55

Both of these are long-standing faults that a recent Git turned into visible ones.

**Bisect never reported its answer.** Git 2.55 prints `is the first 'bad' commit`, quoting the term where earlier releases did not. Gitland matched only the unquoted wording, so a bisect that had found its commit reported nothing and simply looked stuck.

**Stash left untracked files behind.** Gitland passes `--literal-pathspecs` to Git so that a file whose name contains pathspec syntax is treated as a name. Under Git 2.55 that flag stops `git stash push --include-untracked` from removing the untracked files it has just stashed: the stash held them, the working tree still held them too, and the checkout was reported clean. The stash command passes no pathspec of its own, so the flag protected nothing there and is no longer applied to it.

## Validation

- Release build: zero warnings and errors.
- 203 core and real Git integration tests passed, including the workspace scan against real repositories that are clean, dirty, ahead, behind, mid-conflict, detached, without a first commit, and unreadable.
- 248 offscreen native UI checks passed, covering the table's own reading of real repositories, both filters, the confirmation Push all asks for, and the fact that refusing it leaves every remote untouched.
- Setup verified as a GUI-subsystem executable and reported with its SHA-256 checksum.

## A note on what the scan costs

Each row is two Git processes, so a folder of forty repositories would start eighty. The scan runs four repositories at a time rather than all at once, and the watcher re-reads one row rather than the folder, which is what makes leaving the view free and keeps a large workspace from stalling the window while it loads.
