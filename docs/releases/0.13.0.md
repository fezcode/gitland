# Gitland 0.13.0

## Windows release

Download and run **Gitland-Setup-0.13.0.exe**. The installer places Gitland in `%LOCALAPPDATA%\Programs\Gitland`, creates the shortcuts you select, and registers an uninstall entry in Apps & Features. The .NET runtime is included.

## Work on several files at once

Every file row now carries a checkbox. Ticking one changes only the selection — clicking the row still opens its diff, as before. Each group header has a tri-state box that ticks or clears the whole group, and shows `2/5` while part of it is selected. The status bar reports how many files are selected.

Right-clicking a ticked row acts on the whole selection. Right-clicking an unticked one acts on that row alone and leaves your selection untouched, the way a file manager does. Counts appear wherever they help: **Stage 3 files**, **Discard changes in 3 files…**, **Copy 3 paths**, **Clear selection (3)**.

### What a mixed selection offers

A selection can span groups freely, and the menu then offers only the actions that make sense for every row in it:

| Action | Offered when |
| --- | --- |
| Stage · Unstage | every ticked row is unstaged or untracked · every one is staged |
| Discard | no ticked row is conflicted |
| Take ours · Take theirs | every ticked row is conflicted |
| Add to .gitignore | every ticked row is untracked |
| Copy path · Copy file name | always |
| Blame · History · Rename · Reveal | a single row, since they open one view |

So ticking two unstaged files offers staging and discarding; adding a conflicted file withdraws both, because there is no longer one thing they could mean. Copying continues to work and reports the full count.

### Discard follows each row

A selection can hold rows that mean different things — an unstaged row, a staged row, an untracked file. Discard honours each rather than flattening them, and the confirmation says exactly what will happen: *"2 files lose their unstaged edits, and 1 untracked file is deleted."* The permanent option from 0.12.0 still applies to the whole set.

### Selection and refreshes

The selection clears when you open another repository, and after any action that stages, unstages or discards, since those rows have moved or gone. A plain refresh — F5 or the repository watcher — prunes it to rows that still exist instead of wiping it, so a background refresh cannot quietly discard what you ticked.

## A note on how selection is stored

A partially staged file appears in both the Unstaged and Staged groups, and each row opens a different version. A selection entry is therefore identified by its group as well as its path, so the two rows of one file are two independent selections. That is what lets a mixed selection have coherent rules at all.
